# Reasoning SFT of Qwen2.5-3B-Instruct: random vs. selected 15K (course project, Fall 2026)

Repo: https://github.com/yuan-zhou-git/Course_Project_Trustworthy_ML (team repo) for the [Project-Reasoning-SFT-LLM](https://github.com/reds-lab/Project-Reasoning-SFT-LLM) assignment.
We fine-tune Qwen2.5-3B-Instruct on 15K samples from the 100K AceReason-1.1-SFT subset twice, once with a random
subset and once with a cheap, label-free selected subset, and evaluate all three models on the 8 course benchmarks.

> Results tables: see `reports/results.md` (generated by `scripts/aggregate_results.py`). Final report: `reports/REPORT.md`.

## Data selection

`scripts/prep_data.py` (deterministic, seed 20261015) produces both sets from the frozen pool file (sha256 in `pool_stats.json`):

- **random15k**: uniform sample of the whole pool, unfiltered (the required baseline).
- **advanced15k**: math only (`extra_info.category`), exact-duplicate prompts removed, complete conversations that fit
  the 16,384-token cutoff under the Qwen chat template (so the final answer and end-of-turn token survive), stratified by
  source x total-token band (<=4K, 4-8K, 8-16K) with proportional quotas. No model scoring, embeddings or answer keys needed.
  Compute is roughly matched: 107.6M vs 113.4M training tokens per epoch.

Each set ships with a manifest (row ids, filter counts, token quantiles). Exact benchmark overlap was checked: 6 pool rows
match a benchmark question verbatim; 1 landed in each 15K set and was kept and disclosed rather than sanitizing one arm only.

## Training (identical for both arms)

LLaMA-Factory (course-bundled copy, v0.9.4), full-parameter SFT, bf16, DeepSpeed ZeRO-3 (no offload), FlashAttention-2,
Liger kernel (fused linear cross-entropy; needed to fit 16K-token samples on 44 GB L40S GPUs), lr 5e-6 cosine, warmup 0,
3 epochs, global batch 8 (4 GPUs x micro-batch 1 x grad-accum 2), cutoff 16,384, response-only loss (label mask verified).
Configs: `yamls/random15k.yaml`, `yamls/advanced15k.yaml`; launcher: `slurm/train.slurm`. Measured throughput: ~12.7K tokens/s
on 4x L40S, ~8 h per arm.

## Evaluation

Course `eval/` harness (vLLM generation, SymPy grader) with the official settings: temperature 0.6, top-p 0.95, 8 samples,
max 32,768 tokens, seed 0. Our wrapper `slurm/eval_run.slurm` adds strict failure handling, immutable run directories with
manifests, an 8-responses-per-question completeness check and a generation-length summary (`scripts/eval_summary.py`);
`eval.py` was patched by one line to forward the seed to vLLM. `scripts/aggregate_results.py` computes pass@1, pass@8,
the leaderboard-style macro average and a paired question-level bootstrap.

## Reproduce

```bash
sbatch slurm/bootstrap.slurm                                  # envs + data prep + eval smoke test
RUN=random15k   CONFIG=yamls/random15k.yaml   sbatch --gres=gpu:4 slurm/train.slurm
RUN=advanced15k CONFIG=yamls/advanced15k.yaml sbatch --gres=gpu:4 slurm/train.slurm
MODEL=<ckpt> RUN_ID=<name> sbatch slurm/eval_run.slurm
python scripts/aggregate_results.py --root eval_outputs --runs base=base_v1 random=random15k_v1 advanced=advanced15k_v1 --out reports
```

Environment freezes: `envs/train_env_freeze.txt`, `envs/eval_env_freeze.txt`. Compute: Virginia Tech ARC (Falcon L40S/A30).
